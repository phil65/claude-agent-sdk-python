# AGENTS.md

Python SDK for the Claude Code CLI (fork of `claude-agent-sdk-python`). Workflow and codebase
structure: `CLAUDE.md`.

## Strict message parsing

Set `CLAWD_STRICT_MESSAGES=1` in development and CI: an unknown CLI message type then raises
`MessageParseError` instead of being skipped with a warning (the default for users). The test
suite sets it in `tests/conftest.py`. An error from it after a CLI update means a new message type
to model in `models/`.

## Upstream sync

The fork no longer merges upstream (last merge: `05d2eb4`, 2026-01-17). Instead, upstream commits
are reviewed and relevant fixes are ported by hand. The Claude Code CLI and the TypeScript SDK types
are the primary sources for the protocol (rows above); upstream Python is a source of bug fixes.

Review, about monthly or before a minor release:

1. `scripts/upstream_since.sh` lists upstream commits touching `src/` since the recorded sha
   (oldest first, CLI bumps and releases left out).
2. Classify each: bug fix / protocol or message type / feature / docs, CI, tests only. Check by
   reading our code, not by hashes: much is restructured (pydantic models, asyncio instead of
   anyio/trio, stdin always open, skills and agents in the initialize request).
3. Port clear bug fixes and protocol additions with tests, one small commit each, with
   `Upstream: <sha>` in the message. Features and design differences go to the owner.
4. Record the newest reviewed upstream sha and date in the table above (`last reviewed`).

Protocol updates (independent of upstream Python): `python scripts/update_sdk_reference.py`
(diff in `reference/CHANGES.md`), port the delta to `models/`, then
`python scripts/update_cli_version.py <version>` with the matching CLI version, and check the
CLI changelog for SDK-relevant entries. Update both rows above.

Deliberately not taken from upstream (as of `6c1b03f`): trio support, `SessionStore` mirroring,
`client_app` label derivation, `--system-prompt-file`, reading the CLI version from the init
message, the `can_use_tool` shadowing warning. Unknown message types are skipped like upstream, but
only in the client's receive loop (`parse_message` stays strict) and not under
`CLAWD_STRICT_MESSAGES`. Fine-grained tool streaming (upstream reverted its default: it can
400 on proxies and Bedrock/Vertex 4.5 models) is `fine_grained_tool_streaming="auto"` here: on for
Anthropic's first-party API only, decided like the CLI's provider selection
(`uses_first_party_api` in `subprocess_utils.py`).
